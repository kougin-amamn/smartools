# ログの書き方

仕組みの設計は [design/log.md](./design/log.md) にあります。ログの仕組みは `common/log.js` の1ファイルにまとめてあり、全ページ(ツール・ランチャー・一覧)が `site.js` より先に読み込みます。ボタンなどの操作ログは自動で出るので、ページ側では**部品に名前を付けて、結果だけを書く**のが基本です。

## 仕組み(common/log.js)

| 部品 | 役割 |
| --- | --- |
| `log(msg)` / `log.warn(msg, err?)` / `log.error(msg, err?)` / `log.debug(msg)` | 年から始まる時刻を付けてコンソールへ出す。err を渡すと ` [詳細] …` を付け、Error はコンソールで展開できるよう一緒に渡す |
| 履歴 | 直近500行を残し、デバッグ画面(eruda)を開いた時にまとめて出し直す(`window.__logReplay`)。eruda は開いた後のログしか拾えないため |
| 予期しないエラー | `error` / `unhandledrejection` を拾って `log.error` に出す |
| `log.step(name, fn, detail?)` | 時間のかかる処理を実行し、`<name>が終わりました(<detail> / <ms>ms)` か `<name>でエラーが発生しました` を1行で出す。戻り値は `{ok:true, value}` / `{ok:false, error}` |
| 操作の自動ログ | ページ全体のクリックと変更を見張り、部品の名前から操作ログを書く(下表) |

### メッセージの一覧(log.MSG)

`log.js` が出す文言は、すべてファイルの先頭の `MSG` に並べてあります。値が入る所は `{名前}` のような埋め字で、`log.format(文言, {名前: '開始'})` で埋めます。値を渡さなかった埋め字は空になります。

| キー | 文言 |
| --- | --- |
| pressButton / pressLink / press | `{グループ}「{名前}」ボタンを押下しました` / `…のリンクを押下しました` / `…を押下しました` |
| select / check / radio / range / color | `{グループ}「{名前}」を「{値}」にしました` など |
| file / fileCancel | `{グループ}「{名前}」でファイルを選択しました({件数}件 / {大きさ})` / `…でファイルの選択をやめました` |
| group | `「{グループ名}」の`(`{グループ}` に入る前置き) |
| stepDone / stepDoneWith / stepError | `{名前}が終わりました({時間}ms)` / `…({詳細} / {時間}ms)` / `{名前}でエラーが発生しました` |
| uncaught / unhandled / detail / replay | 予期しないエラー、未処理の非同期エラー、` [詳細] {詳細}`、デバッグ画面の区切り |

文言を変える時はここだけを直します。ページ側でも同じ文言を使いたい時は `log(log.format(log.MSG.pressButton, {名前: '…'}))` のように使えます。

`site.js` と `tool-kit.js` はログを使うだけで、ログの仕組みは持ちません。`log.js` が読めなかった時は、`site.js` は何もしないログで代わりに動き、各ページは HTML の読み込み確認が画面に案内を出します。

## 自動で出る操作ログ

| 部品 | ログ |
| --- | --- |
| ボタン(`button`・`[role=button]`) | `「開始」ボタンを押下しました` |
| リンク(`a[href]`) | `「保存」のリンクを押下しました` |
| `data-log` を付けた要素(画像・表のセルなど) | `「サムネイル」を押下しました` |
| チェック | `「自動開始」を ON にしました` |
| 選択肢(select) | `「言語」を「日本語」にしました` |
| ラジオ | `「…」を選択しました` |
| スライダー(離した時) | `「音量」を 80% にしました` |
| ファイル選択 | `「画像」でファイルを選択しました(2件 / 120KB)` |
| 色 | `「文字色」を #ff0000 にしました` |

- **名前の決まり方:** `data-log` → `aria-label` → `<label for>` か囲む `<label>` → `title` → 部品の文字(先頭の ●■▶ などの飾りは外す、24文字まで)。名前が無い部品は出さない(再生位置のスライダーなど)。
- **グループ:** 親に `data-log-group="録音 3"` を付けると `「録音 3」の「削除」ボタンを押下しました` になる。一覧の行は、ファイル名ではなく番号でグループ名を付ける。
- **出さない:** `data-log="off"` を付けた要素と、その中の部品。
- **スライダーの値:** `data-log-unit="%"`(単位)、`data-log-scale="100"`(0〜1の値を%に)、`data-log-value="#表示"`(画面の文字を使う)。
- **対象外:** 文字入力(テキスト・数値・日付・テキストエリア)は打った内容を出さないため、自動では出さない。プログラムから呼んだ `click()` も出さない。
- **順番:** 押下のログが先、ページ側の結果のログが後になる(自動ログはキャプチャで先に動く)。状態で文字が変わるボタンも、押した時の文字で出る。

## ページ側で書くもの

- **結果:** 何が起きたかを、値を括弧に入れて ` / ` で区切る。例: `作業を開始しました(残り 25:00 / 終了予定 20:09)`
- **起動:** 初期化の最後に1回、`起動しました(復元した設定など)`。
- **部品ではない操作:** キー操作や3D空間のタップなど。例: `Escapeキーを押下しました`、`フロアランプをタップしました`。
- **自動のでき事:** 時間切れ、読み込みの完了、権限の結果など。
- 押下のログは書かない。名前が合わない時は `data-log` で名前を付ける。

## 書き方の決まり

- 過去形の普通の日本語文にする(`…しました`)。`[操作]` のようなタグは付けない。重さはレベルで表す。
- `log.warn`: 想定内の失敗や制限(`設定の保存に失敗しました`)。`log.error`: `<何をしていたか>でエラーが発生しました` と Error を渡す。空の `catch {}` で黙らせない。
- `log.debug`: 細かい内部の状態だけ。
- 毎フレーム・センサーの1サンプル・指の移動など、高い頻度のものは出さない。開始・停止・まとめ(`計測を停止しました(合計 120件)`)を出す。
- 時間のかかる処理は `log.step` で所要時間を付ける。
- **個人情報を出さない:** ファイルの中身、入力した文字、正確な位置、ファイル名や曲名は出さず、件数・大きさ・おおよその値・番号を出す。

## 例外として自分で書いている所

| 場所 | 理由 |
| --- | --- |
| `site.js` のカラーテーマの一覧 | 色見本の並びで名前が取りにくいため、一覧は `data-log="off"` にして `「カラーテーマ」の「…」ボタンを押下しました` を書く |
| デスクトップ風ランチャーのメニュー | 項目が `li` で、開いた直後の誤操作を無視する判定があるため、無視しなかった時だけ書く |
| 3D ランチャーのキー操作、3D空間のタップ | 部品ではない操作のため |
