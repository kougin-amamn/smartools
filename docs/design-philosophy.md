# Smartools — サービス・デザインコンセプト

## 1. ブランドコンセプト

**使いやすさを、美しく。**

Smartoolsは、日常で必要になる小さな道具を、ブラウザから手軽に利用できるWebツール集です。

インストールや複雑な準備を必要とせず、必要なときに、必要な機能を、迷わず使えることを目指します。

私たちが考える美しさとは、単に見た目が整っていることではありません。

機能が整理され、操作が自然に理解でき、使う人に余計な負担をかけないこと。その使いやすさの中に、美しさがあると考えます。


## 2. サービスコンセプト

Smartoolsは、次の5つの価値を大切にします。

| コンセプト | メッセージ | 基本方針 |
| --- | --- | --- |
| インストールなし | 思い立ったらすぐ使える | ブラウザだけで利用でき、導入の手間をなくす |
| ユニバーサルデザイン | 誰もが無理なく操作できる | 年齢・経験・利用環境にかかわらず使いやすくする |
| シンプル | 機能が整理され、迷わない | 必要な機能を分かりやすく配置し、複雑さを減らす |
| 実用的 | 道具として信頼できる | 正確性・安定性・応答性を重視する |
| 親しみやすい | また使いたいと思える | 心地よい見た目と自然な操作感を提供する |

### 2.1 インストールなし

思い立ったらすぐ使える。

- Webブラウザから直接利用できる。
- アプリのインストールを必須としない。
- 不要なアカウント登録や初期設定を求めない。
- 利用開始までの操作を最小限にする。

### 2.2 ユニバーサルデザイン

誰もが無理なく操作できる。

- スマートフォン、タブレット、PCに対応する。
- タッチ、マウス、キーボードで操作できるよう配慮する。
- 文字の読みやすさ、色のコントラスト、操作領域を確保する。
- 色だけに依存せず、状態や意味を伝える。
- 利用者の経験や身体的特性によって不必要な障壁を作らない。

### 2.3 シンプル

機能が整理され、迷わない。

- 主要な機能をすぐに見つけられる。
- 操作の選択肢を必要以上に増やさない。
- 情報や設定を適切に整理する。
- 説明がなくても基本操作を理解できるようにする。
- シンプルさのために必要な機能を犠牲にしない。

### 2.4 実用的

道具として信頼できる。

- 正確性と安定性を優先する。
- 操作に対して分かりやすい反応を返す。
- エラーや制約を利用者に適切に伝える。
- 実際の利用場面を想定して設計する。
- 見た目の演出より、道具としての完成度を優先する。

### 2.5 親しみやすい

また使いたいと思える。

- 清潔感があり、心地よい画面を目指す。
- 過度に無機質・事務的な印象を避ける。
- 一貫した操作感によって安心感を生む。
- 必要な範囲で色や動きを活用する。
- 使い続けても負担を感じにくいデザインにする。


## 3. デザイン哲学

**Functional Beauty — 機能美**

Smartoolsでは、使いやすさを追求した結果として生まれる美しさを重視します。

装飾そのものを否定するのではなく、視覚表現に目的を持たせます。

例えば、ストップウォッチの円形ゲージは、時間の経過を直感的に把握するために使用します。一方、情報理解や操作に寄与しないアニメーションは原則として採用しません。

### 3.1 デザイン原則

1. 機能優先 — 視覚表現は機能の理解と操作を支援する。
2. 明快さ — 何ができるか、何が起きているかを分かりやすくする。
3. 一貫性 — 共通する操作や状態には共通の表現を使う。
4. 適応性 — 画面サイズや入力方法の違いに自然に対応する。
5. 節度 — 色、動き、装飾を目的に応じて必要な範囲で使う。

### 3.2 デザイン判断の優先順位

デザイン上の要素が競合する場合、原則として次の順序で判断します。

1. 正確性・安全性
2. アクセシビリティ
3. 操作性・分かりやすさ
4. 情報の視認性
5. サービス全体の一貫性
6. 視覚的な美しさ・演出

ただし、個別ツールの目的や利用状況に応じて調整します。


## 4. ビジュアルデザイン

### 4.1 基本方針

- ミニマルでフラットな表現を基本とする。
- 情報と操作の階層を明確にする。
- 適切な余白によって視認性を高める。
- 装飾的な立体表現や過剰なアニメーションを避ける。
- 操作部品の形状・状態・配置に一貫性を持たせる。

### 4.2 カラー

Smartoolsは紺紫(`#4a4e7a`)を中心とした配色を基本とし、ミント(`#5cc4b6`)などのアクセントカラーを組み合わせます(2026-11-14 に、ネイビーから紺紫へ直した。実装の色は [ui.md](./ui.md) の配色)。

初期の配色検討(今の配色は紺紫。下の色は検討の記録)：

| 用途 | 色 |
| --- | --- |
| ベース | `#E8E8E8` |
| サブカラー | `#5588A3` |
| 基準ブルー | `#004A7C` |

これらはデザイン検討時の基準色であり、実装では共通テーマトークンを優先します。

- 複数のカラーテーマを提供する。
- ライト・ダーク表示に対応する。
- 色の意味をツール間で統一する。
- コントラストと可読性を確保する。

### 4.3 アニメーション

アニメーションは、次の目的がある場合に採用します。

- 状態の変化を伝える。
- 時間や進捗を表現する。
- 操作に対するフィードバックを提供する。
- 情報の関係性を理解しやすくする。

装飾だけを目的とする動きは原則として避け、動きを抑える設定にも配慮します。


## 5. UI・UX設計原則

### 情報設計

- 主要情報を最も分かりやすい位置に配置する。
- 関連する操作をまとめる。
- 必要性の低い情報は視覚的な優先度を下げる。

### 操作設計

- 主要操作を明確にする。
- 操作可能・操作不可の状態を区別する。
- 操作結果を適切にフィードバックする。
- 誤操作を防ぎ、必要に応じて回復手段を用意する。

### レスポンシブ設計

- スマートフォンを含む多様な画面サイズに対応する。
- 画面の向きによって必要なレイアウトを調整する。
- 画面サイズにかかわらず主要操作へアクセスできるようにする。

### アクセシビリティ

- 意味のあるHTML構造を使用する。
- キーボード操作とフォーカス表示に配慮する。
- 文字・色・操作領域の可読性を確保する。
- スクリーンリーダーなどの支援技術への対応を考慮する。


## 6. 例外と拡張

Smartoolsの標準デザインは、実用性と機能美を優先します。

ただし、ツールの目的上、より豊かな視覚表現が必要な場合は例外を認めます。

### DJツール

DJツールは、機器を模した表現や視覚的な演出が操作体験の一部となるため、暫定的な例外とします。

将来的には、よりリッチな表現を中心とした別コンセプトのサイトへの移行を想定します。

### ランチャー

3D本棚・3D美術館などのランチャーは、ツールを探して開く入り口を楽しく見せる物として、例外とします(2026-11-14)。立体表現や演出を使ってかまいません。ただし、ふつうの一覧(フラットな表示)はいつでも選べるようにします。

例外を設ける場合でも、操作性・可読性・基本的なアクセシビリティは維持します。


## 7. AIによるデザイン設計

AIがSmartoolsの新規ツールを設計・改善する際は、この文書を上位の判断基準として扱います。

### 推奨プロセス

1. 目的の理解 — ツールの用途、利用者、利用場面を把握する。
2. 情報・操作の整理 — 主要機能、情報の優先順位、操作の流れを定義する。
3. UI設計 — デザイン哲学と既存UI規約に基づいて構成する。
4. 実装 — 共通コンポーネントと既存のテーマ機構を優先する。
5. 検証 — 機能・操作性・視認性・一貫性を確認する。
6. 改善 — 問題とその理由を記録し、必要な変更を行う。

## 8. 最終的な判断基準

新しいデザインや機能を採用する前に、次の問いを確認します。

- 思い立ったとき、すぐ使えるか？
- 誰もが無理なく操作できるか？
- 機能が整理され、迷わないか？
- 道具として信頼できるか？
- また使いたいと思えるか？
- 見た目の美しさが、使いやすさを支えているか？

Smartoolsのデザインは、使う人のために存在する。

使いやすさを、美しく。
