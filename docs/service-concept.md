# Smartools — サービスコンセプト

見た目と操作の決まりは [デザインコンセプト](./design-concept.md) に分けています(2026-11-16)。この文書は、サービスとして何を目指すかを書きます。

## 1. ブランドコンセプト

**使いやすさを、美しく。**

Smartoolsは、日常で必要になる小さな道具を、ブラウザから手軽に利用できるWebツール集です。

インストールや複雑な準備を必要とせず、必要なときに、必要な機能を、迷わず使えることを目指します。

私たちが考える美しさとは、単に見た目が整っていることではありません。機能が整理され、操作が自然に理解でき、使う人に余計な負担をかけないこと。その使いやすさの中に、美しさがあると考えます。

## 2. サービスコンセプト

Smartoolsは、次の5つの価値を大切にします。

| コンセプト | メッセージ | 基本方針 |
| --- | --- | --- |
| インストールなし | 思い立ったらすぐ使える | ブラウザだけで利用でき、導入の手間をなくす |
| ユニバーサルデザイン | 誰もが無理なく操作できる | 年齢・経験・利用環境にかかわらず使いやすくする |
| シンプル | 機能が整理され、迷わない | 必要な機能を分かりやすく配置し、複雑さを減らす |
| 実用的 | 道具として信頼できる | 正確性・安定性・応答性を重視する |
| 親しみやすい | また使いたいと思える | 心地よい見た目と自然な操作感を提供する |

### 2.1 インストールなし

思い立ったらすぐ使える。

- Webブラウザから直接利用できる。
- アプリのインストールを必須としない。
- 不要なアカウント登録や初期設定を求めない。
- 利用開始までの操作を最小限にする。

### 2.2 ユニバーサルデザイン

誰もが無理なく操作できる。

- スマートフォン、タブレット、PCに対応する。
- タッチ、マウス、キーボードで操作できるよう配慮する。
- 文字の読みやすさ、色のコントラスト、操作領域を確保する。
- 色だけに依存せず、状態や意味を伝える。
- 利用者の経験や身体的特性によって不必要な障壁を作らない。
- 日本語と英語で使える(2026-11-15。[design/i18n.md](./design/i18n.md))。

### 2.3 シンプル

機能が整理され、迷わない。

- 主要な機能をすぐに見つけられる。
- 操作の選択肢を必要以上に増やさない。
- 情報や設定を適切に整理する。
- 説明がなくても基本操作を理解できるようにする。
- シンプルさのために必要な機能を犠牲にしない。

### 2.4 実用的

道具として信頼できる。

- 正確性と安定性を優先する。
- 操作に対して分かりやすい反応を返す。
- エラーや制約を利用者に適切に伝える。
- 実際の利用場面を想定して設計する。
- 見た目の演出より、道具としての完成度を優先する。

### 2.5 親しみやすい

また使いたいと思える。

- 清潔感があり、心地よい画面を目指す。
- 過度に無機質・事務的な印象を避ける。
- 一貫した操作感によって安心感を生む。
- 必要な範囲で色や動きを活用する。
- 使い続けても負担を感じにくいデザインにする。

## 3. サービスの範囲

- Smartools に置くのは、日常の道具として使うツールです。
- 機器を模した表現や演出そのものが体験の中心になるツール(DJツールなど)は、別のサイト [Toolbox Pro](https://github.com/kougin-amamn/toolbox-pro) に置きます(2026-11-11)。
- ランチャー(デスクトップ風・3D本棚・3D美術館)は、ツールを探して開く入り口を楽しく見せる物として置きます。ふつうの一覧はいつでも選べます。

## 4. 最終的な判断基準

新しいツールや機能を採用する前に、次の問いを確認します。

- 思い立ったとき、すぐ使えるか？
- 誰もが無理なく操作できるか？
- 機能が整理され、迷わないか？
- 道具として信頼できるか？
- また使いたいと思えるか？
- 見た目の美しさが、使いやすさを支えているか？

Smartoolsのデザインは、使う人のために存在する。

使いやすさを、美しく。
