# 小説読み上げ(Novel Reader) 設計書

2026-11-07 作成(検証用の試作。カクヨムで試す)。同日に試作を実装

## 概要

Web 小説の1話を、作者のルビと形態素解析で決めた読みで、ブラウザの音声合成で読み上げる。本文は利用者が開いているページからブックマークレットで渡すか、貼り付ける。小説サイトへの通信は増やさない(読者として普通にページを開く以上のことはしない)。

既にある「音声読み上げ」(`text-to-speech`)は、入力した文章をそのまま読む軽いツールのまま残す。形態素解析の辞書(約17MB)を読むので、別のツールにする。

## 課題と方針

| 課題 | 方針 |
| --- | --- |
| 小説サイトの本文を自動で取得するのは、規約で禁止されていることがある(なろう: 14条23項) | ツールから小説サイトへは通信しない。カクヨムは利用者が規約を確認済み(自動取得を直接禁じる条文は無い。負荷・私的使用の範囲外の複製・営利は禁止) |
| ブラウザから他サイトのページは CORS で読めない(カクヨムで「止められた」を確認済み) | 利用者が開いているページの表示から、ブックマークレットで本文を取り出す。予備として貼り付け |
| サービスに負担をかけたくない(利用者の希望) | ブックマークレットは、開いているページの表示を読むだけで通信しない。中継サーバー(Cloudflare Worker)は作らない |
| 本文の要素の名前(クラス名)を確かめられていない | 決め打ちにしない。`.widget-episodeBody` を探し、無ければ `<p>` が一番多く並ぶ要素を本文とみなす |
| ブックマークレットからツールへ本文を渡す | ツールを新しいタブで開き、ツールの「準備できた」の合図を待って `postMessage` で渡す。ツールは送り元がカクヨム(`https://kakuyomu.jp`)の時だけ受け取る。開けない時はクリップボードにコピーし、貼り付けを案内する |
| 音声合成は漢字を読み間違える | 読みの優先順位: 作者のルビ → 形態素解析(kuromoji.js)の読み → そのままの文字 |
| かなだけを渡すと、アクセントや区切りが不自然になることがある | 渡し方を設定で選べるようにし、実機で比べる(下の「読みの渡し方」) |
| Chrome は長い文を1回で読ませると途中で止まることがある | 1文ずつ順に読ませる。読んでいる文を画面で強調し、文を押すとそこから読む |
| 本文は私的使用の範囲で扱う | 本文はメモリの中だけに置き、保存しない・送らない・ログに出さない(ログは文の数・文字数だけ) |

採らなかった案:

- 中継サーバーで本文を取る: 負担と悪用の対策が要り、利用者の希望(負担をかけない)に合わない。
- 既存の「音声読み上げ」に機能を足す: 重い辞書を軽いツールに持ち込むことになる。

## 構成

```
tools/novel-reader/
├── novel-reader.html / .css / .js     画面: 受け取り・貼り付け・本文の表示・再生の操作
├── novel-reader-core.js               DOM を使わない処理: ルビ記法の読み取り・文の区切り・読みの組み立て(Node で試す)
├── novel-reader-bookmarklet.js        ブックマークレットの元(画面に登録用のリンクとして出す)
└── app-icon-novel-reader.svg
```

- 形態素解析: `@patdx/kuromoji@1.0.4`(kuromoji.js の改良版、ES モジュールを jsDelivr から `import()`)。元の `kuromoji@0.1.2` は辞書のアドレスを `path.join` で作り `https://` を壊す不具合があるため使わない。辞書は `kuromoji@0.1.2/dict/` の gzip 12ファイルを自分の読み込み処理で取り、`DecompressionStream` で展開する(届いた物が展開済みならそのまま)。
- 音声合成: ブラウザ標準の `speechSynthesis`(ja-JP の声)。

## 仕様

### 本文の取り込み

- **ブックマークレット:** カクヨムの話のページで押す。作品名・話のタイトル・本文(段落ごと)・ルビ(`<ruby>` の `<rb>` と `<rt>`)を取り出し、ツールを新しいタブで開いて渡す。
- **貼り付け:** 文章を貼る。`|漢字《かんじ》` と `漢字《かんじ》`(なろう・青空文庫・カクヨムの投稿時の記法)はルビとして読む。
- 取り込んだら `本文を受け取りました(段落 120 / 3,400字 / ルビ 15)` を出す(中身は出さない)。

### 読みの組み立て

1. 段落を文に分ける(。！？ と閉じかっこの後、空行)。
2. 文ごとに kuromoji で単語に分け、読み(カタカナ)をひらがなにする。
3. ルビのある所は、解析の結果よりルビを優先する。
4. 読みが無い単語(記号・英字・辞書に無い語)はそのまま。

### 読みの渡し方(設定。実機で比べて初期値を決める)

| 選択肢 | 音声合成に渡す文 |
| --- | --- |
| 原文 | 本文のまま(音声合成が自分で読む) |
| ルビだけかな | ルビの所だけかなにし、ほかは本文のまま |
| すべてかな | 全部を読みのひらがなにする |

### 再生

- 再生・一時停止・停止・前の文・次の文。文を押すとそこから読む。
- 設定: 声・速さ・読みの渡し方(保存する)。
- 読んでいる文を強調し、画面の中に入るよう送る。

## 処理の流れ

1. ツールを開くと kuromoji の辞書を読み始める(`log.step`)。読めるまでは「原文」で読める。
2. 本文を受け取ったら文に分けて表示し、辞書が読めていれば読みを組み立てる。
3. 再生を押すと、今の文から1文ずつ `speechSynthesis.speak` し、読み終えたら次の文へ進む。

## 制限事項

- 形態素解析の読みは文脈で間違えることがある(「今日」きょう/こんにち、人名、数字)。作者のルビがある所は正しい。
- 辞書は約17MB で、初回の読み込みに時間がかかる(ブラウザのキャッシュに残る)。
- iPhone は画面を消すと読み上げが止まることがある。声の種類は端末による。
- ブックマークレットはカクヨムのページの作りが変わると動かなくなることがある。
- 規約の確認は利用者が行った。ツールは本文を保存・送信しない。

## 確認

- `tests/core/novel-reader.test.js`: ルビ記法、文の区切り、読みの組み立て(ルビ優先、助詞の「は」「へ」)。
- `tests/scenarios/novel-reader.js`: 偽のカクヨムのページ(試験のブラウザで `https://kakuyomu.jp` に見せかける)でブックマークレットを動かし、別のサイトの新しいタブへ本文とルビが届くこと、1文ずつ読み進むこと、読みの渡し方、ログに本文が出ないこと、カクヨム以外で押した時の案内。音声合成と kuromoji は偽物。
- `node tests/smoke.js tools/novel-reader`。
- 実機で: ブックマークレットがカクヨムで動くか(Android Chrome・iPhone Safari)、新しいタブへ渡せるか、kuromoji の辞書が CDN から読めるか、どの渡し方が聞きやすいか。
