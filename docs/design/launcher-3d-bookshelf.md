# 3D本棚ランチャー 設計書

状態: 下書き(ヘッダの隠し方が残り。「5. 決めてほしいこと」)。作成 2026-11-07、更新 2026-11-07。

新しい型で書く最初の設計書です。今の動きを要件として書き、`../design-3d.md` の項目で足りない所を洗い出しています。本棚と美術館で共通の作り(ES モジュール、共通の部品、段の進め方)は [launcher-3d.md](./launcher-3d.md) に書き、ここでは本棚だけの事を書きます。

## 1. 概要

- 何のためか: サイトのツールを、書斎の本棚に並んだ本として見せ、選んで開く入口の画面です。
- 誰がどこで: サイトを使う人が、主にスマホ(縦・横)とタブレットで開きます。パソコンでも使えます。
- 迷った時の優先: 文字が読めること > 雰囲気・写実らしさ(2026-11-07 決定)。
- うまくいったと言える目安(案):
  - 開いて数秒で本棚が見え、迷わずに本を選んで開ける。
  - 「眺めて楽しい」と感じる。速く探すのは検索と 2D の一覧に任せる(`../design-3d.md` A)。
  - 待っている間に電池を使い続けない。
- 前提: https で配信。three.js(今は r128)と WebGL を使い、使えない時は 2D の一覧にします。

### やらないこと(2026-11-07 決定)

| やらない事 | 理由 |
| --- | --- |
| 部屋の中を自由に歩き回る操作 | 探すのが遅くなり、酔いやすい。見回しと寄るだけにする |
| 本の並びを使う人が手で変える | 並びはカテゴリ順に決める。手入れの量が増えるため |
| 写真の絵(画像ファイル)の質感 | 通信量が増える。質感は Canvas で描く |

## 2. 基本設計

### 2.1 要件と課題

#### 要件(今の動き)

| 番号 | 要件 | 受け入れの条件 |
| --- | --- | --- |
| R-01 | ツールを本として本棚に並べる | 一覧のツールが、カテゴリごとのマスに本として並ぶ。1マスは1カテゴリ、1マス6冊まで、4段×2列で1台。足りなければ台を増やす |
| R-02 | 本を選ぶ | 本をタップした時、本を引き出して正面に寄り、説明カード(名前・説明・タグ・番号)を出す |
| R-03 | ツールを開く | 引き出した本をもう一度タップした時か、「このツールを開く」を押した時、ツールを開き、開いた回数を記録する |
| R-04 | 前後の本へ | 本を見ている時、横にスワイプするか ← → キーか前後のボタンで、隣の本へ移る |
| R-05 | 本棚に戻す | 本以外の所をタップするか、「本棚に戻す」か Esc を押した時、本を棚に戻して全体の表示に戻る |
| R-06 | 見回す・拡大 | ドラッグで見回し、ピンチ・ホイールで 1〜3 倍に拡大する。拡大している時は「等倍に戻す」が出る |
| R-07 | よく使うツール | 開いた回数の多い3つを、机の上に置く。記録が無い時は一覧の先頭から |
| R-08 | 部屋の物 | 天井の照明・机のアームライト・フロアランプをタップした時、点け消しする。扉をタップした時、前の画面に戻る |
| R-09 | 昼と夜 | サイトのテーマ(明るい・暗い)が変わった時、部屋の明かりと色を切り替える |
| R-11 | 探す(2026-11-07 決定。未実装) | 検索の入口はいつも見える。名前で探すか、カテゴリを選んだ時、候補を出し、選んだ本へカメラが寄って R-02 と同じ状態になる |
| R-12 | ヘッダを出さない(2026-11-07 決定。未実装) | 開いた時、サイトのヘッダは見えない。ヘッダのボタン(テーマ・情報・デバッグ)を使う時だけ出す(出し方は Q6) |
| R-10 | 2D の一覧 | 「一覧」を押した時、ツールを文字で並べた一覧を出す。three.js か WebGL が使えない時は、最初から一覧を出す |

#### 課題と方針

`launcher-3d.md` の E1〜E10 のうち、本棚に関わる物と、`../design-3d.md` で見つけた抜けです。

| # | 課題 | 方針(案) |
| --- | --- | --- |
| B1 | 探す手段が無い(E1) | 検索の入口をいつも見える所に置く(R-11、段 3) |
| B2 | 止まっている時も描画の繰り返しが毎フレーム起きる(E3) | 動いている間だけ回す |
| B3 | 描画の環境が失われた時に戻らない(E4) | 止めて案内を出し、戻ったら作り直す。何度も起きたら一覧にする |
| B4 | 画質の段が無い。画素の細かさの上限(2倍・約260万画素)だけ(E5) | 低・標準・高の段にし、json に置く |
| B5 | 読み上げソフトで使えない(E7) | 2D の一覧を、3D と同じ内容の HTML として使えるようにする |
| B6 | 見た目の決め事が、数値で書かれていない | 作風は今のまま(写実寄り)、部屋にサイトの色を使わない、と決めた(2026-11-07)。光・材料の値を json に移す(段 2) |
| B7 | 動きを減らす設定(`prefers-reduced-motion`)に対応していない | 寄る動きを切り替えだけにする |
| B8 | 押せる大きさの決まりが無い。スマホ縦で本の背が細い(要確認) | 本の背が画面で 24px 未満になる時は、寄ってから選ぶ |

#### 採らなかった案

| 案 | 採らなかった理由 |
| --- | --- |
| 1回のタップですぐ開く | 3D では押し間違いが多い。一度寄って名前を見せてから開く |
| 探すのは 2D の一覧に任せる | ツールが増えると本棚だけでは遠くなる。3D の中でも探せるようにする(2026-11-07) |
| 雰囲気を優先する | 小さな画面で文字が読めないと、選べない(2026-11-07) |
| 模型風(模様を消して単色) | 試作で比べ、今の写実寄りを選んだ(2026-11-07) |
| その間(模様を薄くする) | 同上。スマホの大きさでは今との差が小さい |
| 部屋(壁・床)に紺紫を入れる | 試作で比べ、ランチャーにはサイトの色を使わないと決めた。部屋が暗く重くなる(2026-11-07) |
| 選んだ本をミントで光らせる | 同上。ミントはアクセントとして良いが、ランチャーには使わない(2026-11-07) |

| 項目 | 今 | 案 |

#### 画面の配置

- 3D は画面いっぱい。説明カードは下(スマホ縦)か横(横長)に出ます。
- 本棚が画面に収まる位置へ、カメラが下がります(画角 55°)。

#### 画面の状態

| 状態 | 見え方 |
| --- | --- |
| 読み込み中 | 進み具合の棒と、今している事 |
| 最初 | 本棚の全体と操作のヒント |
| 本を選んだ | 本が手前に出て、説明カード |

### 2.4 処理方式

- 読み込み: ES モジュール。HTML は入口の1本だけで、three.js は `import('three')` で読みます([launcher-3d.md](./launcher-3d.md))。
- 絵: 質感・本の背・表紙は Canvas 2D で描き、テクスチャにします。見本は json です。
- 重さ: 画素の細かさは最大2倍・約260万画素まで。描画は変化があった時だけですが、繰り返し自体は止めていません(B2)。

#### 品質の目標(案)

| 項目 | 目標 |
| --- | --- |
| 最初の表示 | 本棚が見えるまでの時間をログで測り、実機で上限を決める |
| 速さ | 動いている時 60fps、低い画質でも 30fps |
| 止まっている時 | 描画しない |
| 対応ブラウザ | import map が使える物(Safari 16.4・Chrome 89 以降)。古い物は一覧 |

## 4. 制限事項と試験

### 4.1 制限事項

- 3D は読み上げソフトで使えません。2D の一覧で代わりにします。
- three.js は約1.14MB(圧縮前)を読みます。
- 開発環境の描画はソフトウェアです。速さ・発熱・メモリは実機でしか分かりません。

### 4.2 試験

| 番号 | 要件 | 方法 |
| --- | --- | --- |
| T-01 | R-01 | `tests/core/launcher-3d-bookshelf.test.js`: 10・47・200冊の詰め方 |
| T-02 | R-02 | `tests/scenarios/launcher-3d.js`: 本をタップすると説明カードが出る |
| T-03 | R-10 | `tests/scenarios/launcher-3d.js`: three.js が無い時に一覧と警告が出る |
| T-04 | 見た目 | 開発環境で3つの大きさの画面を撮り、前と比べる |
| T-05 | R-03〜R-09 | 実機: 開く → 本を選ぶ → 前後 → 戻す → 照明 → テーマ切り替え → ツールを開く |
