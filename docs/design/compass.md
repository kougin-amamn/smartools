# 方位磁石

2026-11-17 作り変え(計器風の細かい文字盤 → 方角が一目で分かる画面)。

## 1. 概要

端末の向きセンサーで、今向いている方角と北の向きを見せる。方角を調べる人が、数字や細かい目盛りを読まずに分かるようにする。

## 2. 基本設計

### 2.1 要件と課題

| 番号 | 要件 | 前の画面の課題 |
| --- | --- | --- |
| R-01 | 向いている方角が一目で分かる | 「– –°」の数字が主役で、方角の名前は小さい |
| R-02 | 北がどちらかが一目で分かる | 1° ごとの目盛り・30° ごとの数字・NE などで細かく、北が埋もれる |
| R-03 | 主役は1つ | 数字と文字盤の2つが主役を争う |
| R-04 | 説明は重ねない | 同じ説明が3か所 |
| R-05 | 色は M3 の役割だけ | 文字盤が固定の白・灰色 |
| R-06 | 目標の方位を決め、ずれを見られる(前からの機能) | — |

### 2.2 外部仕様

1. **主役(文字盤)**: 円の中に、北を指す大きな針(北側は主の色で塗り、南側は線だけ)。縁に「北・東・南・西」を大きく(北は主の色)、45° ごとに短い線だけ。細かい目盛りと数字は無くす。文字盤は向きに合わせて回り、針はいつも北を指す。
2. **向いている方角**: 文字盤の上の固定の三角が「端末の上の向き」。文字盤の上に、8方位の名前を大きく(「北東」、display-small)、横に角度(「45°」、title)。
3. **主な操作**: 開始前だけ「コンパスを開始」。開始後は「この方位を目標にする / 目標を解除」。
4. **案内**: 1行だけ(開始前は「端末を水平に持って開始してください」、傾き・精度の案内もこの行)。
5. **注意**: いちばん下に磁北の注意。
- 水平の気泡は無くす(傾いた時は案内の行で知らせる)。

### 2.4 処理方式の要点

- 方位の計算・なめらかに追う動きは `compass-core.js`(前のまま)。8方位の名前を足す。

## 3. 詳細設計

| 関数(`CompassCore`) | 役割 |
| --- | --- |
| `dirLabel(h)` | 16方位の名前(ログ用、前のまま) |
| `eightDirectionOf(h)` | 8方位の名前(画面の大きな文字) |

## 4. 制限事項・試験

| 番号 | 試験 |
| --- | --- |
| T-01(R-01) | `eightDirectionOf` が 0→北、44→北東、100→東、350→北 |
| T-02 | 画面が開き、エラーが無い(smoke) |

- センサーは実機でしか確かめられない(要確認)。


## 2026-11-17 デザイン更新

利用者の確認したライト・ダークのイメージに合わせ、文字盤の下へ方角と角度をまとめる。目標設定は利用者の要望により削除する。

- 文字盤は15°刻みの細い目盛り、45°刻みの長い目盛り、細い両針で構成する。上部の固定印は短い線。
- 方角は主色、角度は大きな等幅数字。配色は共通テーマの役割に従う。
- 開始前は未測定を「—」で示し、針を隠す。開始後はセンサー受信時に針を表示する。
- 目標ボタン・マーカー・ずれの表示を削除。方位計算の既存APIは維持する。
- 詳細説明を「使い方・測定について」に折りたたむ。相対方位・傾き・精度の案内は主画面に表示する。
- ヘッダは既存の開閉方式を使用。横向きでは文字盤を左、数値と案内を右へ配置する。
- 開始ボタンの領域を確保し、計測開始による文字盤の移動を抑える。

検証済みは方位計算テスト、構文チェック、模擬DOMでの起動・方位受信・許可拒否・センサー未受信・傾きと相対方位の案内。ブラウザ起動と確認ページへの接続が環境側で失敗したため、360/768/1440px・横向き・ライト/ダークの実描画と実機センサーは未検証。
